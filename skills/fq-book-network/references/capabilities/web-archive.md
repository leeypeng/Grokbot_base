# 网页存档检索与离线保存

## R — 原文依据
来源：`docs/web/web-archive.md`，历史快照、保存与局限段。[原文](https://github.com/hoochanlon/fq-book/blob/master/docs/web/web-archive.md)。短引文：“对于显示css、image并不理想，还是存在一定的局限性。”区分查已有快照、提交当前页面和本地留存三种动作。

## I — 方法解释
获取原始URL和需要的历史时间范围。
先查已有存档，再选择与问题时间相符的快照。
记录原URL、快照时间、存档URL和正文来源。
检查关键图片、CSS、脚本或附件是否缺失，不用标题替代正文核对。
按用途建议网页保存、PDF或截图；历史恢复与保存当前页面不是同一件事。

## A1 — 案例
原书演示在Wayback提交URL和查已有记录，并列出本地网页/PDF/截图方式；测试图片未查看，没有可复核的独立存档结果。合成演练：2019教程页面已删、仅有2021快照，输出时间不匹配与关键截图缺失；没有快照则报告该渠道未找到，不承诺现在提交能重建2019内容。

## A2 — 适用与区分
用于失效文章、旧教程、历史页面版本对照与资料留存。网络本身连接失败先走证据整理。需要当前安装参数时，历史存档只能作背景，应查当前官方资料。用户要完整动态站点备份时，本卡仅说明现有保存方式的缺口。

## E — 执行契约
输入：原URL、目标日期、需要正文或完整页面、是否本地保存。输出快照候选表、时间依据、缺资源清单及保存建议。有快照则核验目标段落；无快照则明确“未找到”，可查原站迁移线索；页面可访问时才考虑保存当前内容。提交至公共存档属于外部发布，必须获得用户明确授权；不提交带令牌、私密参数或登录内容。完成条件：每项历史结论能追到具体时间版本，未找到/未加载明确标注，本地文件可读后才称保存成功。

## B — 边界
不保证所有URL均有快照或可存档；反爬、脚本和缺图会影响完整性。PDF/截图不是可交互整站备份。旧缓存服务及界面标签需现查，不能用历史页面替代当前事实。不会默认将任何用户资料公开存档。
